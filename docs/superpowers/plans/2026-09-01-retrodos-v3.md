# RetroDOS V3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the RetroDOS web prototype around the approved hybrid V3 design, replacing the fake CSS PC with a premium visual asset and delivering a compact responsive library plus a mobile-first player command deck.

**Architecture:** Keep the existing framework-free data model and `RetroDOSCore` helpers. Replace `index.html`, `assets/css/retrodos.css`, and `assets/js/app.js`; preserve `assets/js/catalog.js` and `assets/js/core.js` compatibility. The UI remains a single-page app with library and player views, localStorage persistence, Internet Archive iframe playback, and a best-effort touch command panel.

**Tech Stack:** HTML5, CSS, vanilla JavaScript, Node.js built-in test runner.

**Spec:** `docs/superpowers/specs/2026-09-01-retrodos-v3-design.md`

## Global Constraints

- Work only on branch `dev`; do not merge to `main` without user approval.
- Keep Internet Archive playback inside the page via `https://archive.org/embed/<archiveId>`.
- Do not include commercial game files.
- No framework or build step is required for the browser prototype.
- V3 must not include the V2 fake `.computer` / `.hero-computer` implementation.
- Mobile player must include a collapsible command/touch deck and explicit landscape/fullscreen game mode action.
- Touch key injection into Archive embeds must be labeled best-effort, not guaranteed.
- Preserve favorites/recent localStorage behavior.
